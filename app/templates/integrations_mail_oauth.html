この設定について
Microsoft 365 は基本認証（アプリパスワードによるIMAP）が廃止されたため、OAuth接続が必要です。 各事務所ごとに、自分のOAuthアプリを登録して、その Client ID / Secret をここに入力してください。 自社ドメイン限定（内部アプリ／単一テナント）で登録すれば、プロバイダの審査は不要です。手順は各カードの「登録手順を見る」に記載しています。
※ここは事務所（テナント）ごとの共通設定です。実際の接続（同意）は各担当がマイページから行います。

Google Cloud で OAuth クライアントを作成し、下記の値を登録します。

🔗 取得ページを開く（Google Cloud 認証情報）

{{ redirect_uris.google }}
{% if get_csrf %}{% endif %}
登録手順を見る（Google Cloud）
  1. Google Cloud Console にログインし、プロジェクトを作成（既存でも可）
  2. 「APIとサービス」→「ライブラリ」で Gmail API を有効化
  3. 「OAuth同意画面」→ User Type は 内部（Internal） を選択（自社ドメイン限定なら審査不要）。アプリ名・サポートメールを入力
  4. スコープに https://mail.google.com/（IMAP用）を追加
  5. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ アプリの種類は ウェブアプリケーション
  6. 「承認済みのリダイレクト URI」に、上の①の URI をそのまま登録
  7. 作成後に表示される クライアントID と クライアントシークレット を、上の②③に貼り付けて保存

🟧 Microsoft 365 / Outlook {% if cfg.microsoft and cfg.microsoft.client_id %}設定済み{% else %}未設定{% endif %}

Microsoft Entra ID でアプリを登録し、下記の値を登録します。

🔗 取得ページを開く（Entra ID アプリの登録）

{{ redirect_uris.microsoft }}
{% if get_csrf %}{% endif %}
登録手順を見る（Microsoft Entra ID）
  1. Microsoft Entra 管理センター →「アプリの登録」→「新規登録」
  2. サポートされるアカウントの種類は この組織ディレクトリのみ（単一テナント） を選択
  3. リダイレクト URI（プラットフォーム＝Web）に、上の①の URI をそのまま登録
  4. 「API のアクセス許可」→「アクセス許可の追加」→ Microsoft Graph →「委任されたアクセス許可」で IMAP.AccessAsUser.All・offline_access・User.Read を追加し、管理者の同意を付与
  5. 「証明書とシークレット」→「新しいクライアント シークレット」を作成し、表示される 値（Value） を控える（後で見えなくなります）
  6. 「概要」の アプリケーション(クライアント)ID と ディレクトリ(テナント)ID、④のシークレット値を、上の②③④に貼り付けて保存

保存後、実際の「接続（許可）」は各担当がマイページの「メール連携」から行えるようにします（次段階で提供）。
