# e-Tax 送信試験（テスト送信）環境 申込ガイド

国税（納付情報登録依頼）のAPI連携を**本番に影響なく**完成させるため、
国税庁の送信試験環境を申し込む。手順・必要事項・申込文面をまとめる。

## 申込方法

e-Taxの「電子メールによるお問い合わせ」フォームから、
**ソフトウェア開発業者向けの仕様に関する問い合わせ・テスト送信の申込**として送信する。

- 電子メールによるお問い合わせ: https://www.e-tax.nta.go.jp/toiawase/toiawase3.htm
- お問い合わせ入力フォーム: https://www.e-tax.nta.go.jp/suggestion/toiawase/input_form.html
- ソフトウェア開発業者の方へ（仕様・窓口）: https://www.e-tax.nta.go.jp/shiyo/index.htm

フォームの問い合わせ区分は「ソフトウェア開発（仕様/送信試験）」に相当するものを選ぶ。

## 申込に必要な情報（事前に用意）

| 項目 | 内容（例） |
|---|---|
| 開発者名（法人名） | 税理士法人OKS |
| 担当者名・連絡先 | 浅山直希 / メール・電話 |
| 開発するソフトの概要 | 顧問先管理アプリ（自社利用）から受付システムへ **納付情報登録依頼** を送信 |
| 利用する手続き | 納付情報登録依頼（様式 TEZ500 Ver1.8） |
| 認証方式 | 利用者識別番号＋暗証番号（方式A・電子署名不要の手続き） |
| 接続方式 | 送受信モジュール相当（HTTPSフォームPOST＋XML電文）を自社実装 |
| 送信試験環境の希望 | テスト用の受付システム接続情報（URL）・テスト用利用者識別番号の発行 |

## 送信試験環境を入手したら（こちらで実装する内容）

1. 取得したテスト系URLを `etax_web_client.py` の接続先に設定（本番と切替可能にする）。
2. テスト用の利用者識別番号・暗証番号で **認証（ログイン）電文を確定**
   （引継ぎ情報の正しい送信形態を実観測で確定。本番でのロック懸念なく試行できる）。
3. **TEZ500（納付情報登録依頼）電文の生成**と `datasend` 送信を実装・検証。
4. **即時通知→メッセージボックス**から納付区分番号を取得。
5. 既存の e-Tax 送信履歴UIに接続し、地方税（eLTAX）と同じ操作感で国税も発行可能にする。

## 補足

- 送信試験は本番アカウントに一切影響しない。ロック等の懸念なく認証電文を詰められる。
- 現状のPoCで「拡張機能なしで受付システムと通信できる」ことは実証済み（docs/etax_webapi_design.md）。
- 申込〜環境発行には数日〜要する場合があるため、その間は地方税(eLTAX)本番化等を先行して進められる。
